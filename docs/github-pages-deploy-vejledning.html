1 · Overblik

GitHub Pages understøtter normalt kun publicering fra repo-roden eller en /docs-mappe via Deploy from a branch. Denne løsning omgår den begrænsning ved at bruge GitHub Actions, der uploader en valgfri mappe — i dette tilfælde — direkte som Pages-artifact.

Fordelen er at resten af repo'et (AL-kode, scripts, konfigurationsfiler) ikke er synligt på websitet — kun indholdet af publiceres.

Push til med ændringer i /
↓
GitHub Actions trigger workflow
↓
Checkout → Setup Pages → Upload artifact fra
↓
Deploy til GitHub Pages
↓
Site live på
workflow_dispatch: Workflow'et kan også køres manuelt fra GitHub → Actions-fanen uden at skulle pushe en ændring. Nyttigt til at tvinge et re-deploy.
⚙️

2 · Konfiguration for dette projekt

Alle projekt-specifikke værdier styres fra CONFIG-objektet øverst i denne fils <script>-tag. Ret kun de værdier — resten af dokumentet opdateres automatisk.

VariabelVærdiBeskrivelse
websiteFolder Mappen der publiceres som Pages-root. Kan være en hvilken som helst sti relativt til repo-roden.
workflowFilename Filnavnet på workflow-filen. Bruges i paths-filteret så workflow'et også re-deployer når selve workflow-filen ændres.
branch Den branch der overvåges for push-events og deployes fra.
pagesUrl Den forventede GitHub Pages URL efter deploy. Sættes automatisk af GitHub i steps.deployment.outputs.page_url.
⚠ Ingen secrets nødvendige: Denne løsning bruger ikke PAT eller secrets. GitHub Actions har de nødvendige tilladelser via permissions: pages: write og id-token: write direkte i workflow-filen.
🌐

3 · GitHub Pages-opsætning i repo'et

Før workflow'et kan deploye, skal GitHub Pages konfigureres til at modtage deploys fra GitHub Actions — ikke fra en branch.

  1. Gå til dit repo på GitHub → Settings.
  2. Vælg Pages i venstre menu.
  3. Under Build and deployment, skift Source til:
    • GitHub Actions (ikke "Deploy from a branch")
  4. Klik Save hvis der er en gem-knap — ellers gemmes det automatisk.
Dette er forskellen fra standard-opsætningen: Med Deploy from a branch publicerer GitHub automatisk fra / eller /docs på en valgt branch. Med GitHub Actions er det udelukkende workflow'et der bestemmer hvad der publiceres — og du kan pege på en hvilken som helst mappe via upload-pages-artifact.
📄

4 · Workflow-filen

Opret filen på denne sti i repo'et:

.github/workflows/

Commit og push til . Workflow'et trigger automatisk fordi filen selv matcher paths-filteret.

5 · Forklaring af workflow-blokkene

Blok / feltHvad det gør
on.push.paths Workflow'et kører kun når der pushes filer under / eller workflow-filen selv ændres. Undgår unødvendige deploys ved AL-kode-ændringer.
workflow_dispatch Giver mulighed for at starte workflow'et manuelt fra GitHub → Actions uden at pushe en ændring.
FORCE_JAVASCRIPT_ACTIONS_TO_NODE24 Dæmper deprecation-advarsler om Node 20 i GitHub Actions-loggen. Ingen funktionel betydning.
permissions pages: write og id-token: write er påkrævet for at workflow'et må skrive til GitHub Pages. contents: read giver checkout-adgang.
concurrency.cancel-in-progress: false Sikrer at et igangværende deploy ikke afbrydes af et nyt push. Det nye deploy venter i kø i stedet.
environment: github-pages Knytter jobbet til GitHub Pages-environmentet. url vises som et klikbart link i Actions-loggen efter deploy.
actions/configure-pages@v5 Forbereder GitHub Pages til at modtage et artifact-deploy.
actions/upload-pages-artifact@v3 Uploader indholdet af som et Pages-artifact. Det er her mappen specificeres — ikke i Pages-indstillingerne.
actions/deploy-pages@v4 Publicerer artifactet til GitHub Pages og returnerer den endelige URL i steps.deployment.outputs.page_url.
⚠ path med og uden trailing slash: I upload-pages-artifact angives path: '' uden trailing slash. GitHub Actions håndterer begge dele, men vær konsekvent for at undgå forvirring.
✅

6 · Verificering

  1. Push workflow-filen til — det trigger det første deploy automatisk.
  2. Gå til repo'et → Actions → find workflow'et Deploy Documentation Website og tjek at det kører (gult = i gang, grønt = success).
  3. Klik på det kørende/gennemførte job → deploy → under Deploy to GitHub Pages finder du et klikbart link til den publicerede URL.
  4. Gå til Settings → Pages og bekræft at Source viser GitHub Actions og at der er et grønt flueben med den seneste deploy-URL.

Fejlfinding

SymptomSandsynlig årsagLøsning
Workflow kører ikke ved push paths-filteret matcher ikke de ændrede filer Tjek at du pushede filer under /
Error: Artifact not found Mappen eksisterer ikke i repo'et Tjek at mappen er committed og stavet korrekt (case-sensitiv)
Permission denied på deploy-steget Pages er ikke sat til GitHub Actions som source Gå til Settings → Pages og skift source til GitHub Actions
404 på GitHub Pages URL Ingen index.html i roden af Tjek at /index.html eksisterer
Gammelt indhold vises stadig Browser-cache eller CDN-forsinkelse Vent 1-2 min og hard-refresh (Ctrl+Shift+R)
