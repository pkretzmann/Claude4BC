1 · Overblik

Målet er at holde et separat GitHub-repository — — automatisk synkroniseret med en enkelt mappe () fra et større hoved-repository.

Løsningen bruger GitHub Actions: hver gang der pushes ændringer til stien /** i hoved-repo'et, kører en workflow der kopierer mappeindholdet til mirror-repo'et som ny root.

KomponentVærdi i dette projektBeskrivelse
Kilde-mappeDen mappe der synkroniseres
Mirror repo/Modtager-repository
Trigger-branchBranch der overvåges
Secret-navnGitHub Secret med PAT
Fuldt automatisk: Når workflow-filen er på plads, sker synkroniseringen hands-off ved hvert push der rammer /**. Der kræves ingen manuel handling.

2 · Opret mirror repository

Mirror-repo'et modtager indholdet af kilde-mappen og kan bruges som GitHub Pages-site eller til andre formål.

  1. Gå til github.com og log ind.
  2. Klik New repository (øverst til højre).
  3. Giv repo'et navnet .
  4. Lad det være tomt — ingen README, ingen .gitignore. GitHub Actions opretter indholdet første gang.
  5. Klik Create repository.
⚠ Vigtigt: Repo'et skal være tomt ved oprettelse. Hvis der allerede er en main-branch med commits, kan det første push fra workflow'et fejle med en merge-konflikt.
🔑

3 · Opret Personal Access Token (PAT)

GitHub Actions skal have tilladelse til at skrive til mirror-repo'et. Det gives via et Personal Access Token (PAT) med repo-scope.

  1. Gå til din GitHub-profil → Settings (øverst til højre under dit avatar).
  2. Venstre menu, helt nederst → Developer settings.
  3. Vælg Personal access tokens → Tokens (classic).
  4. Klik Generate new token (classic).
  5. Giv token et navn, fx website-sync, og vælg en udløbsdato.
  6. Sæt scope: ✅ repo (hele blokken — giver læse- og skriveadgang til repositories).
  7. Klik Generate token — kopiér token med det samme, det vises kun én gang.
⚠ Gem token et sikkert sted — fx i en password manager. Hvis du mister det, skal du generere et nyt og opdatere secret'en i trin 4.
🔒

4 · Tilføj secret i hoved-repo'et

PAT'en gemmes som en krypteret GitHub Secret i hoved-repo'et, så den ikke ligger i klar tekst i workflow-filen.

  1. Gå til dit hoved-repo på GitHub.
  2. Klik Settings → Secrets and variables → Actions.
  3. Klik New repository secret.
  4. Udfyld felterne:
    • Name:
    • Secret: indsæt PAT fra trin 3
  5. Klik Add secret.
Case-sensitive: Secret-navnet skal matche præcis det navn der bruges i workflow-filen under secrets.. GitHub skelner mellem store og små bogstaver.
⚙️

5 · Opret workflow-fil

Workflow-filen fortæller GitHub Actions hvornår og hvordan synkroniseringen skal køre. Opret filen på denne sti i hoved-repo'et:

.github/workflows/sync-website.yml

Commit og push filen til -branchen. Herefter trigger workflow'et automatisk næste gang der pushes en ændring under /.

Sådan verificerer du at det virker

  1. Lav en lille ændring i en fil under / i hoved-repo'et.
  2. Commit og push til .
  3. Gå til hoved-repo'et → Actions — du bør se workflow'et køre med et grønt flueben.
  4. Gå til / — filerne fra / bør nu ligge i roden.
⚠ Hvis workflow'et fejler med "Permission denied" eller "Authentication failed", skyldes det typisk at PAT'en er udløbet eller ikke har repo-scope. Generer en ny PAT og opdater secret'en.

6 · Case-insensitiv 404-redirect

GitHub Pages kører på Linux, som er case-sensitive. En mappe der hedder da-DK nås ikke via URL'en /da-dk/. For at håndtere dette oprettes en 404.html i roden af mirror-repo'et, der automatisk redirecter til den korrekte sti.

<!DOCTYPE html>
<html>
<head>
<script>
  const path = window.location.pathname.toLowerCase();
  if (path.includes('/da-dk/')) {
    window.location.replace(
      window.location.href.replace(/\/da-dk\//i, '/da-DK/')
    );
  } else if (path.includes('/en-us/')) {
    window.location.replace(
      window.location.href.replace(/\/en-us\//i, '/en-US/')
    );
  }
</script>
</head>
</html>

Hvordan det virker

  • GitHub Pages viser 404.html når en URL ikke matches.
  • window.location.pathname.toLowerCase() gør hele URL-stien til lowercase før sammenligningen — så DA-DK, da-Dk og Da-DK matches alle.
  • Regex-erstatningen (/\/da-dk\//i) udskifter den forkert-casede del med den korrekte og redirecter.
Placering: 404.html skal ligge i roden af -repo'et — dvs. i / i hoved-repo'et, så den synkroniseres automatisk via workflow'et.
